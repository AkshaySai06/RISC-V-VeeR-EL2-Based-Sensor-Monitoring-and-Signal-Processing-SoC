RISC-V VeeR EL2 Based Sensor Monitoring and Signal
Processing SoC
Detailed Design & Implementation Specification (v2.0 — AXI4-Lite)
Purpose of this document. This is a complete, self-contained implementation brief. An implementation agent should be able to read this document alone
and produce synthesizable RTL, testbenches, firmware, and simulation scripts without asking further questions. Where a choice was open, this document
makes the choice and marks it. Anything genuinely unresolved is collected in Section 16.
Revision note (v2.0): The system interconnect is AXI4-Lite. AHB-Lite is not used anywhere in this design. Note that the VeeR EL2 core's native bus
interface is full AXI4 (64-bit data, bursts, transaction IDs) — it does not speak AXI4-Lite directly. A bridge is therefore a mandatory, first-class component of
this design, specified in Section 6.

1. Introduction
1.1 Background
Sensor-driven embedded systems follow a recurring three-stage pattern: acquire → condition → actuate. A temperature, pressure, or inertial sensor is read
over a serial bus; the raw samples are noisy and must be smoothed; the smoothed value is then converted into a control action such as a fan speed, a valve
position, or a motor drive level.
Building each of these stages as an independent, hand-wired hardware block makes the system hard to integrate and harder to verify. A programmable Systemon-Chip solves this by putting a general-purpose processor in charge of sequencing and decision-making, while dedicated hardware IPs handle the timing-critical
or arithmetic-heavy work.

1.2 What this project builds
A medium-scale RISC-V SoC built around the VeeR EL2 core (CHIPS Alliance, formerly Western Digital SweRV EL2), with an AXI4-Lite interconnect and the
following slaves:
Block

Instruction Memory (IMEM)

The three bolded blocks are the custom IPs of this project. UART, Timer, and GPIO are supporting infrastructure and should be kept deliberately simple.

1.3 Design goals
1. Correctness first. Every IP gets a standalone unit testbench before it is integrated.
2. Strict AXI4-Lite compliance. Every slave obeys VALID/READY handshake rules, never deasserts VALID before READY, keeps payload stable while VALID is
high, and returns OKAY unless a genuine error occurs.
3. Memory-mapped, register-driven. No IP has hidden side channels; every interaction between the processor and an IP happens through documented
registers.
4. Parameterized, not hardcoded. Tap count, data width, FIFO depths, and address bases are Verilog parameters.
5. Simulation-first. The whole system must run to completion in an open-source simulator (Verilator or Icarus) with no FPGA board required.
6. One reusable slave shim. All six peripherals share a single, verified AXI4-Lite register-interface module. Protocol bugs are then fixed once, not six times.

1.4 Explicit non-goals
No RTOS. Bare-metal C with a single main() loop.
No cache coherency, no DMA engine, no multi-master arbitration on the peripheral bus.
No floating point. The FIR uses fixed-point Q1.15 arithmetic.
No physical sensor required for sign-off — a behavioural I²C sensor model in the testbench is sufficient.
No place-and-route or timing closure. Synthesis (Yosys) as a lint/feasibility check only.
No AXI4 exclusive access, no QoS, no regions, no out-of-order completion.

5.7 Mandatory protocol rules
Every master and slave in this project must obey all of the following. These are the rules the assertions in §14.3 check.
1. Once VALID is asserted it must remain asserted until the handshake completes. A master may not withdraw AWVALID because it changed its mind.
2. Payload must be stable while VALID is high and READY is low. AWADDR , WDATA , WSTRB , ARADDR , RDATA , RRESP , BRESP do not change mid-wait.
3. READY may be asserted before or after VALID, and may be withdrawn if no handshake occurred. Slaves are allowed to be combinationally ready.
4. There must be no combinational path from an input VALID to the corresponding output READY within a slave if it would create a loop through the
interconnect. The simplest safe policy, and the one this design uses: slaves register their READY.
5. AW and W are independent channels. A slave must not require AW before W, or W before AW. The reusable shim in §6.5 handles this by waiting for both.
6. B must not be issued before both AW and W have been accepted. Exactly one B response per write.
7. Exactly one R beat per AR (AXI4-Lite has no bursts; there is no RLAST ).
8. All channels return to their reset state on ARESETN low: all VALID signals deasserted. READY may be anything.
9. No slave may stall a handshake for more than 32 cycles (design rule for this project, not an AXI requirement — it makes deadlock bugs surface quickly).
Common bug to avoid #1: asserting BVALID as soon as AWVALID && AWREADY without waiting for W . The write has not happened yet. Common bug to
avoid #2: clearing a "write pending" flag on BVALID instead of on BVALID && BREADY . The master may not be ready. Common bug to avoid #3: making
AWREADY combinationally depend on WVALID and WREADY combinationally depend on AWVALID . That is a deadlock.

6.2 The bridge — why it is needed
The VeeR EL2 core in its AXI4 build presents a full AXI4 master interface:
64-bit WDATA / RDATA with 8-bit WSTRB
burst support: AWLEN / ARLEN up to 255, AWSIZE / ARSIZE , AWBURST / ARBURST
transaction IDs: AWID / BID , ARID / RID
WLAST / RLAST

sideband: CACHE , PROT , QOS , REGION , LOCK
AXI4-Lite has none of the burst, ID, or LAST signalling and is 32-bit here. The bridge reconciles the two. Skipping it and wiring the core straight to Lite slaves will
not work.

6.3 Bridge — read path
State machine: R_IDLE -> R_ISSUE -> R_WAIT -> (repeat for each beat) -> R_RESP

1. Accept AR. On arvalid && arready , capture arid , araddr , arlen , arsize , arburst . Set beat_total = arlen + 1 , beat_idx = 0 .
2. Compute the address for this beat. For arburst == INCR : addr = araddr + (beat_idx << arsize) . For arburst == FIXED : addr = araddr . WRAP is not
supported; if it appears, complete the transaction with RRESP = SLVERR on every beat. (With ICCM/DCCM and caches disabled, WRAP should never be issued.
Assert on it.)
3. Split into 32-bit Lite reads. Each 64-bit AXI4 beat becomes two AXI4-Lite reads at addr and addr+4 . Issue the low word first. Assemble rdata_64 =
{hi_word, lo_word} . - If arsize < 3 (the core requested fewer than 8 bytes), only one Lite read is needed; replicate the 32-bit result onto both lanes of RDATA
and let the core select. Drive rdata_64 = {word, word} .
4. Return the beat. Drive RID = captured id , RVALID = 1 , RLAST = (beat_idx == beat_total-1) , RRESP = the worse of the two Lite responses ( DECERR >
SLVERR > OKAY ).
5. Advance. On rvalid && rready , increment beat_idx ; if more beats remain, go back to step 2.
Only one AR is accepted at a time ( D15 ). Deassert ARREADY while a burst is in flight.

6.4 Bridge — write path
State machine: W_IDLE -> W_COLLECT -> W_ISSUE_LO -> W_ISSUE_HI -> W_BRESP

1. Accept AW. Capture awid , awaddr , awlen , awsize , awburst . Deassert AWREADY .
2. Accept W beats. For each 64-bit WDATA with 8-bit WSTRB : - Low word: if WSTRB[3:0] != 0 , issue an AXI4-Lite write of WDATA[31:0] with WSTRB[3:0] to addr .
- High word: if WSTRB[7:4] != 0 , issue an AXI4-Lite write of WDATA[63:32] with WSTRB[7:4] to addr+4 . - A lane with an all-zero strobe is skipped
entirely — do not issue a Lite write with WSTRB = 0 . This matters: a 32-bit store from the core arrives as a 64-bit beat with only one lane enabled.
3. Accumulate the response. Keep a running worst-case bresp .
4. On WLAST , once all Lite writes for that beat have received their B responses, drive BID = captured id , BRESP = accumulated , BVALID = 1 .
5. Clear on BVALID && BREADY , then reassert AWREADY .

Required behaviour of the shim:
Write: assert s_awready and s_wready together only when both s_awvalid and s_wvalid are high and no write is already in flight. On that handshake, emit
a one-cycle reg_wen with reg_waddr = s_awaddr[ADDR_LSB+REG_BITS-1:ADDR_LSB] . Then drive s_bvalid the following cycle with s_bresp = (s_wstrb != 4'hF
|| reg_err) ? SLVERR : OKAY . Hold until s_bready .
Read: on s_arvalid with no read in flight, assert s_arready for one cycle and emit reg_ren with reg_raddr . One cycle later, latch reg_rdata and assert
s_rvalid with s_rresp = reg_err ? SLVERR : OKAY . Hold until s_rready .

This one module carries all the protocol risk. Verify it exhaustively (§14.1) and the six peripherals become easy.

6.6 Interconnect
axi4lite_interconnect is a 1-to-N demux, not a crossbar. It needs:

Write path: decode AWADDR into a one-hot select. Route AW and W to the selected slave. Route the selected slave's B back. Because only one write is
outstanding (D15), a single registered wsel_q is sufficient — capture it on the AW handshake, use it to route W and B , clear it on BVALID && BREADY .
Read path: decode ARADDR into a one-hot select. Capture into rsel_q on the AR handshake. Route R back from rsel_q . Clear on RVALID && RREADY .
Decode miss: route to axi4lite_err_slave , which accepts the address and data, then returns DECERR on B or R . It must still consume the W beat, or the
bus deadlocks.
Critical: W routing must follow wsel_q captured from the AW handshake, not a fresh decode of AWADDR . By the time W arrives, AWADDR may no longer be
valid.

6.7 Memory slaves
axi4lite_sram : synchronous single-port RAM, parameterized DEPTH_WORDS . Honours WSTRB per byte lane. One-cycle read latency, so RVALID lands one cycle
after the AR handshake. Backdoor $readmemh task for testbench preload.
axi4lite_sram_dp : two independent AXI4-Lite slave ports sharing one memory array. Port A is read-only (IFU), port B is read-write (interconnect, but writes are
unused in the baseline). No arbitration is needed because the underlying array is true dual-port.

Tie-off discipline: an AXI port tied off incorrectly is a silent hang, not a visible error. For every unused slave port on the core, drive all READYs low and all
VALIDs low. For every unused master port, drive all VALIDs low and all READYs high. Add an assertion that no VALID ever rises on a tied-off port.

11. Data Paths
Each numbered path below is a distinct flow of payload through the system. The agent should be able to point at each one in a waveform.

DP-1 — Instruction fetch
IMEM port A --> axi4lite R channel (32b) --> bridge_ro assembles two words
--> ifu_axi_rdata[63:0] --> Core IFU --> decode/execute

Read-only. If the IFU issues a burst ( ARLEN > 0 ), the bridge emits 2 × (ARLEN+1) Lite reads and returns ARLEN+1 beats with RLAST on the final one.

DP-2 — Sensor acquisition (external → CPU)
Sensor --sda--> i2c sda_i --> bit FSM shift register --> RXR register
RXR --> reg_rdata --> shim RDATA --> interconnect --> bridge (lane replicate)
--> lsu_axi_rdata[63:0] --> CPU register

Two passes yield MSB and LSB; firmware combines them into a signed 16-bit sample. Throughput is bounded by SCL (100 kHz) — roughly 200 µs for the full 2byte read sequence.

DP-3 — Sample push (CPU → FIR)
CPU rs2 --> lsu_axi_wdata[63:0] + wstrb[7:0]
--> bridge: selects the enabled 32-bit lane, issues one Lite write
--> interconnect (wsel_q = FIR) --> shim reg_wen/reg_wdata
--> FIR DATA_IN latch --> delay line x[n]

A single 32-bit sw instruction. The bridge must not issue a second Lite write for the disabled lane.

DP-4 — FIR computation (internal)
delay_line[k] --+
+--> multiplier --> 40-bit accumulator (16 iterations)
coef_mem[k]

---+

accumulator --> arithmetic right shift (SHIFT) --> saturate to 16 bits --> DATA_OUT

18 clocks, entirely internal. No bus activity.

DP-5 — Result read (FIR → CPU)
FIR DATA_OUT --> reg_rdata --> shim RDATA --> interconnect --> bridge
--> lsu_axi_rdata --> CPU register (sign-extended)

DP-6 — Control output (CPU → PWM → actuator)
CPU (duty computed in software) --> bridge --> interconnect --> PWM shim
--> PWM DUTY shadow register --[at counter wrap]--> duty_active
--> comparator vs count --> pwm_raw --> polarity/enable --> pwm_out pin

DP-7 — Telemetry (CPU → host)
CPU --> bridge --> interconnect --> UART shim --> TXDATA --> TX FIFO
--> shift register --> uart_tx pin --> host

DP-8 — Memory access (stack, globals, buffers)
CPU <--> lsu_axi_* <--> bridge <--> interconnect <--> DMEM

This is the only path where WSTRB values other than 4'hF occur, from sb and sh instructions.

12. Control Paths
Control paths carry decisions, not payload.

CP-1 — Write address decode and routing
m_awaddr[31:28], m_awaddr[15:12]
--> axi4lite_decoder --> wsel (one-hot, or dec_err_w)
--> on (m_awvalid && m_awready): wsel_q <= wsel
--> W channel routed by wsel_q
--> B channel routed back from wsel_q
--> on (m_bvalid && m_bready): wsel_q cleared, AWREADY reasserted

CP-2 — Read address decode and routing
m_araddr --> decoder --> rsel (one-hot, or dec_err_r)
--> on (m_arvalid && m_arready): rsel_q <= rsel
--> R channel routed back from rsel_q
--> on (m_rvalid && m_rready): rsel_q cleared, ARREADY reasserted

Read and write routing are fully independent — a read to the FIR may be in flight while a write to the UART is outstanding.

CP-3 — Back-pressure
slave deasserts s_awready/s_wready --> interconnect deasserts m_awready/m_wready
--> bridge holds AW/W valid, payload stable
--> bridge deasserts lsu_axi_awready/wready
--> core stalls the store pipeline

Symmetrically for reads via ARREADY and RVALID . Nothing is dropped; every stall propagates as a handshake stall.

CP-4 — Error responses
unmapped address

--> dec_err --> axi4lite_err_slave
accepts AW, consumes W, returns BRESP = DECERR
accepts AR,

returns RRESP = DECERR

peripheral WSTRB != F --> shim reg_err

--> BRESP = SLVERR

FIR write while busy

--> BRESP = SLVERR

--> fir reg_err

--> bridge propagates the worst response of all split beats to the core
--> core takes a load/store access-fault trap

Response precedence: DECERR > SLVERR > OKAY . When one 64-bit AXI4 beat splits into two Lite transfers, the beat's response is the worse of the two.

CP-5 — Burst splitting sequence (read)
AR accepted (ARLEN=n, ARSIZE=3)
for beat in 0..n:
Lite read at addr + beat*8

-> word_lo

Lite read at addr + beat*8 + 4

-> word_hi

drive RDATA = {word_hi, word_lo}, RLAST = (beat == n), RVALID = 1
wait for RREADY
ARREADY reasserted

CP-6 — I²C command sequencing
CPU writes CMD --> byte FSM decodes STA/STO/RD/WR/ACK
--> byte FSM issues primitives to bit FSM
--> bit FSM steps on scl_tick from the prescaler
--> on completion: TIP=0, IF=1, RxACK captured
--> CPU polls STAT (or takes irq_i2c)

CP-7 — FIR start/done handshake
reg_wen to DATA_IN (with CTRL.EN=1, STATUS.IDLE=1) --> start pulse
--> FSM: IDLE -> MAC(x16) -> ROUND -> IDLE
--> DONE=1, irq_fir=1 (if IRQ_EN)
--> CPU reads DATA_OUT --> reg_ren clears DONE --> irq_fir=0

CP-8 — PWM shadow register update
CPU writes DUTY/PERIOD/PRESCALE --> shadow registers, no immediate effect
--> counter reaches period_active --> wrap_pulse
--> active <= shadow ; STATUS.WRAP <= 1 ; irq_pwm (if IRQ_EN)

CP-9 — Sampling cadence
Timer mtime increments (prescaled) --> compare vs mtimecmp --> timer_int
--> firmware detects (polled via MTIME_LO) --> one sample iteration
--> firmware writes new mtimecmp = mtime + PERIOD_US --> timer_int deasserts

CP-10 — Reset sequencing
rst_n (async) --> 2-FF reset synchronizer (deassert synchronous to clk)
--> aresetn to core, bridges, interconnect, all slaves
--> all VALID signals low, all in-flight state cleared
--> core fetches from rst_vec = 0x00000000

Hold reset asserted for at least 16 clocks in the testbench.

14. Verification Plan
14.1 Unit level
TB

Must demonstrate

tb_axi4lite_regif

Highest priority. Write with AW-before-W, W-before-AW, and simultaneous. Read and write in flight together. Backpressure on B and R held
for 1, 2, and 10 cycles. WSTRB != F → SLVERR. reg_err → SLVERR. No protocol assertion fires under randomized VALID/READY delays.

tb_axi4lite_err_slave

Returns DECERR on both B and R; consumes the W beat so the bus does not deadlock

tb_axi4_to_axi4lite

Single 32-bit write on each lane; 64-bit write with both lanes; write with one lane strobed off issues only one Lite write; single read; burst read
with ARLEN = 1, 3, 7 ; RLAST correct; ID returned unchanged; SLVERR and DECERR propagate with correct precedence

tb_axi4lite_interconnect

Decode to each slave; independent read and write in flight; unmapped address → DECERR; W follows wsel_q not a fresh decode

tb_axi4lite_sram

Byte, halfword, word writes with correct WSTRB behaviour; read-after-write

tb_i2c

Against a behavioural I²C slave model: single-byte write, single-byte read, 2-byte read with repeated START, NACK handling, correct SCL
frequency, correct START/STOP timing

tb_fir

Impulse response equals the coefficient set; step response settles to Σh[k]; random-input output matches a golden reference from the same
Python script; saturation flagged; FLUSH clears the delay line; write-while-busy returns SLVERR

tb_pwm

Measured duty within ±1 count for duty = 0, 1, PERIOD/2, PERIOD, PERIOD+1; shadow registers do not glitch mid-period; polarity inversion;
FORCE mode

tb_uart

Loopback at 115200 through an external UART model; FIFO full/empty flags; overrun flag; no double-pop on a backpressured read

tb_timer

mtime increments at the prescaled rate; timer_int asserts and deasserts correctly; the 64-bit read retry loop converges

tb_gpio

Direction control, input synchronization, edge and level interrupts

Each unit TB should drive its AXI4-Lite port through a small reusable master BFM ( tb/models/axi4lite_master_bfm.sv ) offering write(addr, data, strb, resp)
and read(addr, data, resp) tasks with randomizable handshake delays. Write the BFM once, use it in every TB.

14.2 Integration level ( tb_soc_top )
The system testbench instantiates soc_top plus: - an I²C sensor model ( tb/models/i2c_sensor_model.sv ) returning a programmable 16-bit value: a clean ramp,
a ramp plus pseudo-random noise, or a step; - a UART monitor that decodes uart_tx and prints to the console; - a PWM duty monitor measuring high time
over a full period, reported as a percentage; - $readmemh preload of IMEM from sw/main.hex .

14.3 Assertions ( rtl/bus/axi4lite_assertions.sv , bound to every AXI4-Lite port)
1. AWVALID stays high until AWREADY ; likewise WVALID , ARVALID , BVALID , RVALID .
2. AWADDR , WDATA , WSTRB , ARADDR stable while VALID high and READY low.
3. RDATA , RRESP , BRESP stable while VALID high and READY low.
4. Exactly one B response per accepted AW + W pair (counter-based check).
5. Exactly one R beat per accepted AR .
6. BVALID never rises before both AW and W have handshaked.
7. No VALID is high in the cycle after ARESETN deasserts.
8. No handshake stalls for more than 32 cycles.
9. WSTRB is never 4'b0000 on a peripheral port (the bridge must have filtered it).
10. FIR: BUSY and IDLE are never both high.
11. PWM: duty_active <= period_active + 1 at all times.
12. I²C: scl_oe and sda_oe never drive a logic 1 (open-drain discipline).
13. Tied-off core ports: no VALID ever rises on sb_axi_* or dma_axi_* .

14.4 Coverage targets
100% of reachable FSM states and legal transitions in the two bridges, the shim, I²C, FIR, and PWM.
All register offsets in each IP written and read at least once.
Both 32-bit lanes exercised through the bridge (address bit 2 = 0 and 1).
Bridge read path exercised with ARLEN = 0 and at least one ARLEN > 0 .
All three response codes ( OKAY , SLVERR , DECERR ) observed at the core boundary.
FIR: both positive and negative saturation reached.

15.3 Acceptance criteria
The project is complete when:
1. make lint is clean (no warnings other than those explicitly waived in verilator.vlt ).
2. Every unit testbench prints PASS , with the AXI4-Lite protocol assertions bound and active.
3. make sim runs test_full_loop to completion with no X-propagation and no assertion failure.
4. The UART transcript shows filtered values with measurably lower variance than the raw values on a noisy input, and the PWM monitor reports a duty that
tracks the filtered value.
5. docs/register_map.md matches the RTL (offsets, reset values, access types).
6. README.md explains how to reproduce every result from a clean clone, and documents the AXI4 → AXI4-Lite bridge as the one place where full AXI4 is handled.

Appendix C — Instruction to the Implementing Agent
Implement the system described above. Work milestone by milestone (§15.4); do not start a milestone until the previous one's tests pass. For each RTL
module, write the module and its unit testbench together, and run the testbench before moving on.
Treat §2 as binding: AXI4-Lite is the SoC interconnect. Do not introduce AHB anywhere. The only place full AXI4 appears is the bridge in §6, which
exists solely because the VeeR EL2 core's native port is AXI4.
Bind the assertion set from §14.3 to every AXI4-Lite port from the very first testbench onward — not at the end. Most bugs in this design are handshake bugs,
and they are invisible without assertions.
If you find a genuine contradiction in this document, state it explicitly, choose the interpretation that keeps the design simplest, and record the decision in
README.md under "Deviations". Do not silently change a register offset, reset value, or bit position.
